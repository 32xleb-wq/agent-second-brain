# Нужно ли регистрировать вебхук?
Нет. Никаких доп. «регистраций» в n8n нет. Варианта два:

1) **Тестовый вызов**
   - В узле **Webhook** нажми **Listen for test event** → появится **Test URL**.
   - Этот URL работает **один раз** и только пока горит режим прослушки.
   - Используй его из Postman/cURL/HTTP Request узла → сработает цепочка.

2) **Продакшн‑вызов**
   - Переведи воркфлоу в состояние **Active (toggle сверху)**.
   - Используй **Production URL** из узла Webhook.
   - Пока воркфлоу активен, этот URL постоянный и принимает запросы.

Если видишь **“is not registered”** — либо не нажал **Listen for test event** (в тесте), либо воркфлоу **не активирован** (в проде), либо ты дергаешь **не тот URL/путь**.

# Базовые правила и чек‑лист

1) **HTTP‑метод должен совпадать.**  
   В узле Webhook выбрал **POST** → зовёшь POST. Ошибка **405 Method not allowed** = метод не совпал.

2) **Путь (Path) — часть URL.**  
   n8n формирует URL вида `https://твой-домен/webhook[-test]/<path>`.  
   Меняешь `Path` в узле — меняется URL. Копируй URL заново.

3) **Тело запроса.**  
   – JSON: отправляй `Content-Type: application/json` и корректный JSON.  
   – Форм‑данные/файлы: используй `multipart/form-data` (Webhook узел умеет принимать бинарь).  
   – Внутри потока данные берёшь как `{{$json}}` или `{{$binary}}`.

4) **Ответ клиенту.**  
   Есть два режима:
   - В самом Webhook: **Respond → When Last Node Finishes** — n8n сам вернёт выход последнего узла.
   - Или поставь узел **Respond to Webhook** и верни свой JSON/код/заголовки.  
   Если клиент ждёт недолго — отвечай быстро (200) и продолжай работу асинхронно.

5) **Таймауты.**  
   Многие клиенты роняют запрос через 10–30 сек. Если твой поток долгий (генерация картинок и т.п.), сделай паттерн:
   - Webhook → **Respond to Webhook (200 OK, “accepted”)** → дальше тяжёлая работа → результат отправь отдельно (почта/Telegram/HTTP Callback) или храни по Job ID.

6) **Статус/коды.**  
   Возвращай 2xx, если всё ок; 4xx — для ошибок клиента; 5xx — если внутреннее. В **Respond to Webhook** можно задать `Status Code`.

7) **Безопасность.**  
   – Ограничь доступ: Basic Auth, секрет в заголовке, IP‑фильтр на прокси.  
   – Для внешних сервисов с подписью (Stripe, Telegram и т.п.) проверяй сигнатуру в воркфлоу.

8) **Активные/неактивные воркфлоу.**  
   – **Test URL** работает только в редакторе и один раз.  
   – **Production URL** работает только у **Active**‑воркфлоу.  
   – При дубликате воркфлоу следи, чтобы активен был **тот**, чей URL ты дергаешь.

9) **Типичные ошибки и их смысл**
   - **is not registered** — неActive/не нажал Listen, либо URL/Path не тот.  
   - **404 could not be found** — ошибка в URL/Path.  
   - **405 Method not allowed** — метод не совпал.  
   - **No binary data was found** — ожидал бинарный ответ/ввод, а его нет (проверь Response Data/Property Name).  

# Мини‑пример «правильного» теста
1) Узел **Webhook**: Method **POST**, Path `generate-image`.  
2) Нажми **Listen for test event** → скопируй Test URL.  
3) Отправь POST JSON:
   ```json
   {"prompt": "fire"}
   ```
4) После Webhook поставь **Respond to Webhook** с `Status Code: 200`, `Response: {{$json}}` — для быстрой проверки.

Если нужно связать два воркфлоу (отдельный «принимает» и отдельный «шлёт»):
- В принимающем возьми **Production URL** (и активируй его).
- В отправляющем используй узел **HTTP Request** → POST на этот Production URL, с нужным телом.

Этого достаточно: копировать правильный URL, совпадение метода, активировать прод или включить тест‑прослушку, вернуть корректный ответ. Всё остальное — опционально.
