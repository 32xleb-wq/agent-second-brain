# Как это делается

## 1) Связка n8n ⇄ GetCourse
Вариантов два — и обычно используют оба:

- **Исходящие запросы в GetCourse** из n8n через **HTTP Request**  
  GetCourse даёт API и **секретный ключ**. Через HTTP Request создаём/обновляем пользователя, добавляем в курс, навешиваем теги и т. п. (ключ генерируется в аккаунте GetCourse). citeturn1search0turn1search1

- **Входящие события из GetCourse** в n8n через **Webhook**  
  GetCourse умеет отправлять **callbacks/webhooks** на ваши URL — например, при оплате, регистрации, подписке на рассылку и т. д. Эти события ловим нодой **Webhook**, дальше обрабатываем логикой/ИИ. citeturn1search0

> Док‑пруфы: в хелп-центре GetCourse есть статьи про наличие API и про секретный ключ API. citeturn1search0turn1search1

## 2) Где “живет” сам ИИ‑бот
Обычно бот «живет» **вне** GetCourse (Telegram/WhatsApp/сайт‑виджет/ваш лендинг), а n8n — это «мозг и шина»:
- вход: сообщение пользователя (Webhook → Function/Code),
- мысль: LLM (OpenAI/Anthropic через соответствующие ноды HTTP/OpenAI),
- память: БД (Supabase/Postgres/Redis) — у тебя уже есть опыт с Supabase 👍,
- выход: ответ в канал + синхронизация статуса в GetCourse (создать/найти пользователя, поставить тег, оформить заказ/присвоить доступ).

## 3) Базовый скелет воркфлоу в n8n

1. **Webhook (IN)**: принимает `message`, `user_id`, `channel`.  
2. **Function**: нормализует юзера и ищет его в БД (Supabase) по `phone/email/messenger_id`.  
3. **HTTP Request → GetCourse (find/create user)**: если нет — **создать** пользователя, если есть — **обновить** (поля/теги). citeturn1search0  
4. **LLM (OpenAI/HTTP Request)**: формируем ответ (темы курса, FAQ, апселлы, поддержка).  
5. **Business Logic**: правила — если намерение “покупка/запись”, то:
   - **HTTP Request → GetCourse**: создать заказ/выдать доступ/повесить тег. citeturn1search0
6. **Ответ пользователю**: Telegram/WhatsApp/API виджета.  
7. **Логирование**: пишем диалог и метаданные (intent, score, product_id) в БД.

## 4) Настройка авторизации для HTTP Request
- В GetCourse создаёшь **API Secret Key** (лучше отдельный под n8n).  
- В n8n в **Credentials (HTTP)**: домен вашего аккаунта + ключ (как query‑параметр или header — как требует конкретный метод из их хелпа). citeturn1search1

> Примечание: у GetCourse есть разные регионы доменов (`.ru`, `.io`, и т. п.), в интеграциях иногда указывают регион явно — это норм. citeturn1search26

## 5) Что именно можно делать через API GetCourse
Из коробки: **создавать/обновлять пользователей и заказы, вешать теги, выдавать доступы, принимать callbacks** — ровно то, что нужно для автоматизации продаж из бота. citeturn1search0

## 6) Важные нюансы продакшена
- **Идемпотентность**: привязывай пользователей по стабильному ключу (email/phone/messenger_id), чтобы не плодить дублей.  
- **Retry & DLQ**: на Webhook‑потоках ставь Retry (429/5xx) и dead‑letter queue (можно простой Table).  
- **Анти‑дубль заказов**: перед созданием заказа проверяй существование по внешнему `order_id`.  
- **Версионирование промптов**: промпт в KV‑хранилище + метка версии в логах диалога.  
- **PII/безопасность**: не логируй полный номер карты/адреса; секреты — только в Credentials.
