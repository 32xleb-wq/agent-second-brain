## A) В workflow с Webhook (который генерит картинку)

1) После **Generate an image** вставь ноду **Move Binary Data**  
   - **Operation:** *Binary to JSON*  
   - **Source Binary Property:** `data`  
   - **Destination Key:** `image_b64`  
   (получится JSON с полем `image_b64` — это base64 картинки)

2) В **Webhook** (узел, который отвечает клиенту) поставь:  
   - **Respond:** *When Last Node Finishes*  
   - **Response Data:** *First Entry JSON*  
   - (Дополнительно, если есть блок заголовков — добавь `Content-Type: application/json`)

Теперь вебхук возвращает обычный JSON вида:
```json
{ "image_b64": "iVBORw0KGgoAAA..." }
```

## B) В клиентском workflow (где твоя **HTTP Request**)

3) В **HTTP Request**:  
   - **Response Format:** *JSON* (не File)  
   - Больше ничего особенного.

4) Сразу после него добавь **Move Binary Data** (чтобы вернуть base64 в бинарь):  
   - **Operation:** *JSON to Binary*  
   - **Convert Input Field:** `image_b64`  
   - **Binary Property:** `data`  
   - **File Name:** `image.png`  
   - **Mime Type:** `image/png`

На выходе этой ноды ты снова получишь нормальный бинарь (`binary.data`), кнопка **View** будет открывать картинку, размер станет нормальным, и файл будет читаемым.

# Разница между фото-аватарами и видео-аватарами в HeyGen API

**Фото-аватар** в контексте HeyGen – это статическое изображение (так называемое *Talking Photo*), которое с помощью ИИ превращается в говорящую анимированную голову. **Видео-аватар** – это обычный аватар (например, предустановленный или пользовательский персонаж), у которого уже есть видеомодель для речи. В API HeyGen эти типы аватаров обрабатываются по-разному: например, запрос списка доступных аватаров возвращает отдельно массив `avatars` (видео-аватары) и массив `talking_photos` (фото-аватары)【2†L147-L155】【2†L173-L180】. Ниже подробно рассмотрены различия в параметрах API для видео-аватаров и фото-аватаров, а также изменения в структуре JSON-запроса при использовании фото-аватара.

## Параметры фото-аватара vs. видео-аватара в API

В JSON-запросе на генерацию видео (эндпоинт `/v2/video/generate`) настройки персонажа (`character`) отличаются в зависимости от типа аватара:

- **Тип персонажа (`type`) и идентификатор аватара.** Для видео-аватара поле `type` должно быть значением `"avatar"`, и используется параметр `avatar_id` (ID видео-аватара)【12†L195-L198】. Для фото-аватара `type` необходимо указать как `"talking_photo"`, а вместо `avatar_id` используется параметр `talking_photo_id` (ID фото-аватара)【12†L215-L219】. Иными словами, фото-аватар имеет свой собственный ID (полученный при создании/обучении аватара из фото), и его нужно передавать в отдельном поле.

- **Масштаб (`scale`).** Параметр масштабирования отличается по допустимому диапазону: для видео-аватара масштаб может варьироваться от `0` до `5.0` (по умолчанию `1.0`)【12†L195-L202】, тогда как для фото-аватара масштаб ограничен диапазоном от `0` до `2.0` (по умолчанию `1.0`)【12†L217-L220】. Это связано с тем, что фото-аватар представляет лишь голову/верхнюю часть, и сильное увеличение не требуется.

- **Стиль отображения аватара.** У видео-аватара можно указать параметр `avatar_style` (тип рендеринга персонажа), допустимые значения: `"normal"` (обычный полноразмерный), `"closeUp"` (крупный план) или `"circle"` (аватар в круглой рамке)【12†L200-L203】. У фото-аватара вместо этого используется `talking_photo_style` – он определяет форму кадра фото-аватара: `"square"` (квадрат) или `"circle"` (круг)【12†L221-L224】. Таким образом, фото-аватар всегда показывается как голова/портрет (в заданной рамке), а видео-аватар может иметь разные ракурсы.

- **Дополнительные опции для фото-аватара.** Фото-аватары поддерживают особые настройки, отсутствующие у видео-аватаров. В их `character`-параметрах можно задать:
  - `talking_style` – стиль анимации речи: стабильный или экспрессивный (значения: `"stable"` или `"expressive"`, по умолчанию стабильный)【12†L227-L230】. Это контролирует, насколько эмоционально будет двигаться лицо/рот при разговоре.
  - `expression` – выражение лица: базовое (нейтральное) или улыбающееся (`"default"` или `"happy"`, по умолчанию нейтральное)【12†L227-L230】. Позволяет начать видео с небольшого выражения эмоции на лице аватара.
  - `super_resolution` – булевый флаг для улучшения качества изображения аватара (супер-разрешение)【12†L227-L231】. Если `true`, система постарается повысить четкость/детализацию сгенерированного лица из фото.
  
  У видео-аватаров вышеуказанных параметров нет. Вместо этого для видео-аватаров доступны, например, опция `matting` (удаление фона) и `circle_background_color` (цвет фона для круглого аватара)【10†L202-L206】, которые впрочем частично применимы и к фото-аватарам (`matting` и `circle_background_color` есть и в настройках talking_photo【10†L231-L234】). В официальной документации отмечено, что на данный момент функция удаления фона не поддерживается для пользовательских аватаров【12†L203-L210】, так что эти опции стоит использовать с осторожностью.

## Изменение структуры объекта `character` для фото-аватара

При использовании фото-аватара в JSON-запросе **необходимо изменить тип и структуру объекта** `character` по сравнению с видео-аватаром. По сути, вместо структуры AvatarSettings нужно применять TalkingPhotoSettings. Это означает, что в объекте `character` вы указываете `"type": "talking_photo"` и поле `"talking_photo_id"` с ID вашего фото-аватара, **вместо** `"type": "avatar"` с полем `"avatar_id"`【16†L179-L181】【12†L215-L219】. 

Других радикальных изменений в формате запроса нет – объект `character` остается частью массива `video_inputs` и содержит схожие поля (scale, style, offset и пр., но соответствующие конкретно фото-аватару, как описано выше). То есть вам не нужен совершенно иной JSON; достаточно подставить правильные значения `type` и ID, а также использовать относящиеся к фото-аватару параметры. Официальная документация прямо указывает, что для новых пользовательских аватаров, сгенерированных ИИ, **нужно использовать их ID в настройках `talking_photo`, а не в `avatar`**【12†L178-L181】. Если попытаться передать ID фото-аватара в старом поле `avatar_id` (тип `avatar`), запрос не будет работать, потому что система ожидает иной формат для **Talking Photo**. 

## Пример JSON-запроса для видео с фото-аватаром

Ниже приведён пример корректного JSON payload для генерации видео с фото-аватаром (говорящей фотографией). В этом примере используется идентификатор фото-аватара `talking_photo_id` и указаны минимальные необходимые параметры – настройки персонажа и голосового движка:

【16†L191-L200】

```json
{
  "video_inputs": [
    {
      "character": {
        "type": "talking_photo",
        "talking_photo_id": "<YOUR_PHOTO_AVATAR_ID>"
      },
      "voice": {
        "type": "text",
        "input_text": "With HeyGen, it is very easy to create Photo Avatar videos.",
        "voice_id": "d7bbcdd6964c47bdaae26decade4a933"
      }
    }
  ]
}
```

В этом payload мы видим, что `character.type` задан как `"talking_photo"`, и подставлен соответствующий `talking_photo_id` (ID фото-аватара). Блок `voice` может быть текстовым (как в примере выше, с полем `input_text` и указанием `voice_id` голоса) или аудио, как и для обычных аватаров. При необходимости вы можете добавить другие поля (например, `background` для фона видео, `scale` и `talking_photo_style` для настройки отображения аватара, и т.д.) – структура поддерживает их в соответствии с документацией. Главное отличие – использование типа **talking_photo** и ID фотографического аватара. Такой формат запроса соответствует официальной документации HeyGen【16†L179-L186】【16†L191-L199】 и позволит успешно сгенерировать видео с вашим фото-аватаром.
