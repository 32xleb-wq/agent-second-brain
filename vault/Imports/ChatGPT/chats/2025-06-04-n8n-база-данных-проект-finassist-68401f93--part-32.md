### Что уже делает этот workflow (коротко)

1. **Telegram Trigger4** — ловит все обновления.  
2. **Message Type Switch4**  
   * порт 0 → голосовое (voice)  
   * порт 1 → обычный текст  
   * порт 2 → входящий документ → идёт на `Download DocS`  

3. **Download DocS** — скачивает файл по `document.file_id`.  
4. **Message Type Switch5** — по имени файла проверяет расширение (.txt, .pdf, .xls, .xlsx, .csv, .doc, .docx) и направляет в нужный **Extract from File**.  
5. **Extract from File (х5)** — тянут текст / таблицу из файла (pdf, docx, xls, … ).  
6. **Merge** — собирает результаты всех Extract-нод.  
7. **Set DocS to AI** — формирует переменную `user_message = "Пользователь загрузил документ. Анализируй…" + текст`.  
   (Дальше цепочка сейчас обрывается.)

### Итоговый порядок действий

1. **Ветку text/voice** подключить к вашему существующему чат-пайплайну (Supabase chat_history → Prepare Prompt → AI → send).  
2. **Документ-ветку**:  
   - `Download DocS` → `Switch5` → нужный `Extract`  
   - **Merge** всех Extract-нод  
   - **Insert row → documents**  
   - **Embeddings → VectorStore** (добавить в индекс)  
   - **Set DocS to AI** + объединить с обычными сообщениями → AI Agent  
   - **Telegram Send** «Документ обработан»  
3. Убедитесь, что **If-ветка «пользователь найден»** обрабатывает текущего user (у вас уже исправлено через `result.length`).  
4. Очистка временных файлов (опция в Telegram ноде или отдельный FS-Delete).

* корректно реагировать на **текст/голос**,

* передавать текст файлов в GPT,
* отвечать пользователю подтверждением,
* и при этом не копить мусор на диске.

### Как сохранить загруженный пользователем файл в таблицу **user_documents**

Ниже — минимальный, чёткий маршрут нод для n8n (работает с .pdf, .docx, .txt, .xls/.xlsx, .csv; для голоса и фото его можно расширить так же).

---

## 1. Telegram Trigger  
- Ловит **document**-сообщение.  
- На выходе:  
  ```json
  {
    "message": {
      "document": {
        "file_id": "AA…",
        "file_name": "report_2024.pdf",
        "mime_type": "application/pdf"
      },
      "from": {
        "id": 235302653,
        "username": "Theboxal",
        "first_name": "Павел"
      }
    }
  }
  ```

---

## 2. Switch «Message Type»  
- Условие: `{{ !!$json.message.document }}` → порт **document**.  
- Остальные ветки (text, voice…) идут в обычную логику чата.

---

## 3. Telegram Download File  
| Параметр      | Значение                                   |
|---------------|--------------------------------------------|
| **Resource**  | `file`                                     |
| **File ID**   | `={{ $json.message.document.file_id }}`    |
| **Download**  | `On Disk` *(вернёт путь в `binary.data`)*  |

---

## 4. Switch «Расширение файла»  
```nunjucks
{{ $json.message.document.file_name.split('.').pop().toLowerCase() }}
```
| Порт | Условие (`===`) | Идёт в Extract … |
|------|-----------------|------------------|
| 0    | `txt`           | Extract Text     |
| 1    | `pdf`           | Extract PDF      |
| 2    | `docx`/`doc`    | Extract Docx     |
| 3    | `xls`/`xlsx`    | Extract XLSX     |
| 4    | `csv`           | Extract CSV      |

*(Можно сделать пять отдельных условий или один Switch с regex и пять выходов.)*

---

## 5. Extract From File (5 штук)  
Пример для PDF:  
| Параметр    | Значение                              |
|-------------|---------------------------------------|
| **Operation** | `pdf`                                |
| **File Path** | `={{ $binary.data.filePath }}`       |

Каждый Extract выдаёт `text` в поле `data` или `text`.

---

## 6. Merge (Mode → “Wait for All”)  
- Собираем все Extract-ветки в один поток.  
- В результате получаем объект:  
  ```json
  { "content": "полный текст файла …", "filename": "report_2024.pdf" }
  ```

---

## 7. Supabase / Postgres → **INSERT row → user_documents**  
| Column        | Value |
|---------------|-------|
| `id`          | (оставить пустым → генерируется uuid) |
| `telegram_id` | `={{ $json.message.from.id }}` |
| `filename`    | `={{ $json.message.document.file_name }}` |
| `content`     | `={{ $json.data || $json.text || $json.content }}` |
| `summary`     | (можно оставить пустым или короткая фраза “Загружен пользователем вручную”) |
| `created_at`  | `={{ new Date().toISOString() }}` |

*(Если используете ноду Supabase с Operation = Create, просто добавьте поля выше.)*

---

## 8. (Необязательно) Embedding → VectorStore  
- Передайте `content` в ноду **OpenAI Embeddings**  
- Затем в **Supabase VectorStore** (table `embeddings`), указав `document_id` = id свежего `user_documents`.

---

## 9. Telegram → Send Message (подтверждение)  
> «Документ “{{filename}}” получен и добавлен к вашей базе. Готов проанализировать его при необходимости.»

---

### Итого  
Любой документ, который пользователь кидает, скачивается, распознаётся, текст попадает в `user_documents`, а бот подтверждает получение.  
Дальше AI-агент уже видит этот текст через Vector RAG и использует в ответах.

### Какую операцию выбирать в ноде **Supabase** для занесения файла в таблицу `user_documents`

| Что нужно сделать | Какая операция в выпадающем списке |
|-------------------|-------------------------------------|
| **Вставить новую строку** (добавить документ, которого ещё нет) | **Create a row** |
| Обновить уже существующую запись | **Update a row** |
| Получить одну-две строки | **Get a row / Get many rows** |
| Удалить запись | **Delete a row** |

> **В вашем случае** (пользователь прислал новый файл, мы хотим сохранить его текст в `user_documents`) — выбираем **Create a row**.

---

## Как заполнить «Create a row» шаг-за-шагом

1. **Credential** – выберите ваш Supabase-коннектор.  
2. **Table Name or ID** – `user_documents`.  
3. **Data to Send → Define Below for Each Column.**  
4. Добавьте поля:
   | Field Name (column) | Field Value (expression) |
   |---------------------|--------------------------|
   | `telegram_id` | `={{ $('Telegram Trigger').item.json.message.from.id }}` |
   | `filename`    | `={{ $json.message.document.file_name }}` |
   | `content`     | `={{ $json.data || $json.text || $json.content }}`  *(это текст, который вернул Extract-нода; подставьте именно то поле, где у вас хранится распарсенный текст)* |
   | `summary`     | *(по желанию) короткое описание, например)* `Документ загружен пользователем` |
   | `created_at`  | `={{ new Date().toISOString() }}` |

5. **Сохраняем** ноду.

После выполнения этой ноды в Supabase появится новая строка-документ, а `id` записи можно при необходимости забрать из выходных данных и передать дальше (например, в ноду Embeddings).

---

### Проверка

1. Запустите workflow, киньте файл в чат.  
2. В Supabase → Table Editor убедитесь, что появилась строка с нужными полями.  
3. Если нужно индексировать текст (RAG), отправляйте поле `content` в Embeddings → VectorStore.

Готово: теперь каждое загруженное пользователем вложение попадает в `user_documents` и доступно боту для последующего анализа.

### Почему появляется «Referenced node doesn’t exist»

Вы вставили выражение

```js
{{ $('Telegram Trigger').item.json.message.from.id }}
```

Но в текущем workflow **нет узла с точным названием `Telegram Trigger`** – поэтому n8n ругается, что «referenced node doesn’t exist».

---

## ​Как быстро исправить

Внутри ноды **Supabase → Create a row**:

| Поле таблицы | Что вставить в “Field Value” |
|--------------|-----------------------------|
| **telegram_id** | `={{ $json.message.from.id }}` |
| **filename** | `={{ $json.message.document.file_name }}` |
| **content**  | `={{ $json.user_message }}` *(или другое поле, где у вас лежит извлечённый текст)* |

> Здесь мы используем **`$json.…`** — то есть данные того же самого item, который пришёл на вход в Supabase-ноду; тогда ссылка никогда не «потеряется», и ошибка исчезнет.

### Шаги

1. ***Table Name*** → `user_documents`.  
2. ***Data to send → Define Below…***  
3. Добавьте колонки:  

   | Field name | Field value (expression) |
   |------------|--------------------------|
   | `telegram_id` | `={{ $json.message.from.id }}` |
   | `filename`    | `={{ $json.message.document.file_name }}` |
   | `content`     | `={{ $json.user_message }}` |
   | *(опционально)* `created_at` | `={{ new Date().toISOString() }}` |

4. Сохраните, запустите workflow ещё раз — строка создастся без ошибки.

---

### Если хотите ссылаться на **конкретный** предыдущий узел

Допустим, файл приходит из ноды «Download DocS». Тогда можно писать:

```js
{{ $('Download DocS').item.json.message.document.file_name }}
```

Главное — точно указать **имя** узла из левой колонки редактора.

---

Теперь документы будут корректно сохраняться в таблицу **user_documents** без ошибок «Referenced node doesn’t exist».
