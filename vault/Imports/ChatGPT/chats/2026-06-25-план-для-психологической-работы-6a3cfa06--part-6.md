Да. Это важная штука. Это называется не просто задача, а **проект / составная задача / цепочка действий**.

И это надо заложить, но **простым способом**, без усложнения.

## Как это должно быть в системе

Есть два типа задач:

### 1. Простая задача

Например:

> Прочитать 15 минут  
> Написать 3 тезиса  
> Прогуляться 10 минут

У неё один шаг, можно быстро выполнить.

### 2. Составная задача / проект

Например:

> Сделать заготовки еды на неделю

У неё есть подзадачи:

```text
Проект: Заготовки еды на неделю

1. Выбрать меню
2. Составить список продуктов
3. Проверить, есть ли контейнеры
4. Заказать/купить контейнеры
5. Купить продукты
6. Подготовить кухню
7. Приготовить еду
8. Разложить по контейнерам
9. Записать, что сработало / что не сработало
```

И самое важное: система должна показывать **не весь проект сразу**, а **следующий шаг**.

Например:

> Сегодня не “готовить на неделю”.  
> Сегодня: “составить список продуктов на 10 минут”.

Вот это прям ключ. Иначе мозг видит огромную задачу и говорит: “Пошло оно нахуй”.

## Как это добавить в MVP

Минимально:

У задачи должно быть поле:

```text
Тип задачи:
- простая
- составная
```

Если составная — появляются:

```text
Подзадачи
Порядок выполнения
Статус каждой подзадачи
Следующий шаг
Прогресс проекта %
```

## Для Lovable потом можно дать так

```text
Добавь поддержку составных задач / проектов.

У задачи может быть тип:
- simple task
- project / multi-step task

Если это project, пользователь может добавить подзадачи.

У каждой подзадачи:
- title
- status: not started / in progress / done
- estimated minutes
- energy level: авария / низкая / средняя / высокая
- note

На карточке проекта показывай:
- название проекта
- общий прогресс в %
- следующий шаг
- список подзадач
- кнопку “Добавить подзадачу”
- кнопку “Разбить проект автоматически”

Пример проекта:
“Заготовки еды на неделю”

Подзадачи:
1. Выбрать меню
2. Составить список продуктов
3. Проверить контейнеры
4. Купить/заказать контейнеры
5. Купить продукты
6. Приготовить еду
7. Разложить по контейнерам
8. Записать выводы

Главный UX-принцип:
Не показывать пользователю весь проект как давление. Всегда выделять один следующий честный шаг.
```

## Как это связано с твоей системой

Это прям идеально ложится в нашу логику:

**большая задача → разбить → выбрать следующий шаг под энергию → засчитать прогресс.**

То есть:

- низкая энергия: составить список продуктов;
- средняя энергия: заказать контейнеры / продукты;
- высокая энергия: готовить;
- авария: открыть заметку “меню на неделю” и записать одну идею.

Фиксируем: завтра в MVP это можно добавить как **Projects / Составные задачи**, но не делать сложный Notion. Просто parent task + subtasks + next step.

### Этап 1 — “Вернуться к жизни”

- контакт с задачей;
- время;
- микрошаг;
- возвращение после отката;
- регулярность;
- не обесценить.

## Что добавить в карточку задачи

Сейчас карточка хорошая, но не хватает двух вещей:

### 1. “Следующий шаг”

На карточке должно быть не просто название задачи, а прямо:

```text
Следующий шаг:
Открыть список анализов и выбрать лабораторию.
```

Это снижает ступор.

### 2. “Заметка / след прогресса”

Кнопка:

```text
+ след прогресса
```

Туда потом:

- текст;
- фото;
- ссылка;
- голос;
- скрин.

Для MVP хотя бы текст.

## Что попросить Lovable сейчас

Вот короткий промпт на доработку главной:

```text
Доработай главный экран “Сегодня”.

Сделай его не просто списком задач, а “Пультом дня”.

Структура главного экрана:

1. Компактный верх:
- дата
- короткая фраза: “Не идеально. Честный следующий шаг.”
- текущий режим дня
- статус чек-ина

2. Блок “Навигатор дня”:
Кнопки:
- Утренний чек-ин
- Собрать план
- Мне плохо
- Итог дня

3. Блок выбора ресурса:
- Авария
- Низкая
- Средняя
- Высокая
- Отдых

Убери дублирование большой кнопки “Выбрать энергию”, если чипы выбора энергии уже есть.

4. Блок “Три честных шага на сегодня”:
Показывать максимум 3 основные задачи:
- здоровье
- психика
- дело жизни

Каждая карточка задачи должна показывать:
- направление
- название
- уровень энергии
- время
- следующий шаг
- прогресс
- кнопки: “микрошаг”, “начать”, “варианты”
- кнопка “+ след прогресса”

5. Отдельный блок “Восстановление сегодня”:
Показать один минимальный, один средний и один большой вариант отдыха.
Для отдыха использовать кнопки:
- “попробовал”
- “помогло”
- “не зашло”
- “заметка”

6. Блок “Мягкие итоги дня”:
- контакт с направлениями
- важные минуты
- микрошаги
- возвращения после отката
- главная победа дня

7. Кнопку “Мне плохо” сделать меньше и не перекрывать карточки. Можно заменить на маленькую floating SOS/Откат-кнопку справа снизу выше нижней навигации.

Главный принцип:
Экран должен помогать человеку быстро понять состояние и выбрать следующий шаг, а не перегружать длинным списком задач.
```
