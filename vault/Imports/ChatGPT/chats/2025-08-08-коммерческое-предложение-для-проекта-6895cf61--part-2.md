## Куда смотреть, если нужен «автодозвон + живой диалог бота»  

| Категория | CPaaS-платформы | Почему подходит | Что придётся учесть |
|-----------|----------------|-----------------|---------------------|
| **“Из коробки” WebSocket-поток (идеально для GPT/ASR/TTS)** | **Twilio Programmable Voice** <br>**Vonage Voice API** | • REST-метод `/Calls` — запускаем исходящий вызов по номеру из базы. <br>• Дальше платформы отдают аудио в **двусторонний WebSocket-поток**: вы получаете 8 kHz µ-law пакеты от клиента и можете тут же вернуть озвученный ответ TTS.  | • Минутный тариф выше среднего (≈ 0.018–0.022 € / DE mobile). <br>• KYC/TrustHub и GDPR-DPA надо заполнить. <br>• Twilio — регионы IE1 (Ирландия) и АU1, Vonage — PoP во Франкфурте. |  
| **Дешевле, тоже WS-stream** | **Telnyx Call Control** <br>**SignalWire Voice** | • Такой же формат: REST-dial → JSON/WS-events → RTP-to-WS. <br>• Латентность < 150 мс, цены ~-20 % к Twilio/Vonage. | • Примеров кода меньше; SDK в основном на GO/Python/Node. |
| **Готовый «голос-бот движок» + EU хостинг** | **Voximplant** | • JS-сценарии исполняются на стороне облака; можно подключить свой GPT через WebSocket или HTTP. <br>• В EU-кластер входит дата-центр во Франкфурте. | • Платформа исторически «русифицирована» — уточните, устроит ли заказчика. |
| **Нативный немецкий SIP-провайдер** | **sipgate.io** | • Очень дешёвые локальные DID-ы. <br>• Простые Webhook-события. | • Нет стрима по WS → нужен свой RTP-→WS прокси (например, drachtio + FreeSWITCH). |
| **Бюджетный вариант, если задержка не критична** | **Zadarma**, **Plivo** | • REST-dial, низкий opex. | • Тоже нет WS-стрима → прокладка. |

### Почему WebSocket-стрим так важен  
* Он избавляет от промежуточного **Asterisk/FreeSWITCH** (не нужно конвертировать RTP → WS).  
* Латентность «речь → GPT → TTS» держится < 1 с, что делает диалог естественным.  

> **Twilio** даёт двусторонний поток через `<Connect><Stream>` или API **Stream Resource** — аудио уходит к вам и обратно в реальном времени. citeturn6search0  
> **Vonage** реализует то же в **WebSocket Voice API**: 2-way поток + JSON-события `answered`, `hangup`, `audio`. citeturn9search0  

### Как связать с n8n  
1. **HTTP Request** node → `POST /Calls` (Twilio) или `POST /v1/calls` (Vonage) — запускаем вызов.  
2. В payload указываем `eventUrl` / `statusCallback` → **Webhook** node в n8n (получаем стадии звонка).  
3. **WebSocket** node — держит стрим; на входе: аудио → ASR; полученный текст → OpenAI node; ответ → TTS; TTS-аудио отправляем обратно в тот же WS.  
4. После `hangup` — **Google Sheets/CRM** node фиксирует статус и ссылку на запись.  

### Рекомендации по выбору провайдера  
| Критерий | Что считать «нормой» для MVP |
|----------|------------------------------|
| Задержка round-trip (speech↔bot) | ≤ 1 с |
| Тариф исходящий на DE-mobile | ≤ 0.02 € / мин |
| Наличие EU-PoP + готовый DPA | Обязательно |
| Поддержка двустороннего WS-stream | Желательно |

**Если нужны «быстро в прод и без прокси»** — берите **Twilio** или **Vonage**.  
**Если важнее цена** — протестируйте **Telnyx** или **SignalWire**.  
**Если хочется сразу TTS/ASR на русском** — смотрите **Voximplant** (но проверьте, подходит ли под GDPR-требования заказчика).  

Сообщи, какие ограничения (цена, регуляторика, региональный номер) критичны — помогу выбрать окончательно и составить точную схему вызова в n8n.

### Что означает ошибка  

```
Problem running workflow  
Cannot read properties of undefined (reading 'execute')
```

n8n падает в тот момент, когда **внутри какого-то узла** он пытается обратиться к полю `execute` у объекта, который оказался `undefined`.  
Чаще всего это случается, когда в выражении (Expression) написано что-то вроде


или внутри Function-/Code-узла вы пишете

```js
items[0].json.execute
```

— а такого свойства на самом деле нет.

### Типичные причины

1. **Опечатка в Expression**  
   `{{$node["Extract Video Script"].execute}}` → должно быть `.json` или `.parameter`.
2. **Узел раньше не выполнялся**  
   Вы обращаетесь к данным из узла, который по условию выше «проскочил» (Skip). Тогда `$node["..."]` вернёт `undefined`.
3. **Перешёл на новую версию n8n**  
   В > v1.0 некоторые старые Function-узлы могут возвращать данные иначе; проверяем, что возвращаем `return items;`.
4. **Кастомный/комьюнити-узел не загрузился**  
   При апдейте пакета node мог «отвалиться»; тогда его объект приходит `undefined`, и runner не видит метода `execute`. Переустановите пакет:

   ```bash
   npm install n8n-nodes-имя_пакета --save
   docker exec -it n8n npm install ...
   ```
