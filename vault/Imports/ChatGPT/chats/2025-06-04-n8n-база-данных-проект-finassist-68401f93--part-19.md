## Переписка

### ChatGPT — 2025-06-18 15:20

**Почему снова падает импорт**

* n8n ≥ 1.90 перешёл на «UI-параметры» (`columnsUi`, `valuesUi`, `queryParametersUi` и т. д.).  
* Наши Supabase/Postgres-ноды в JSON всё ещё содержат старые плоские атрибуты `columns` / `values`.  
* При загрузке нода пытается пройтись по `propertyValues[itemName]`, но получает строку (или `undefined`), отсюда *propertyValues[itemName] is not iterable*.

---

## Как быстро починить

### 1) Поменять стратегию: вместо «Insert/Upsert» → использовать `executeQuery`

В режиме `executeQuery` узлу **не нужны** массивы `columnsUi/valuesUi`, мы просто передаём готовый SQL-запрос — и ошибка исчезает.

```jsonc
{
  "parameters": {
    "operation": "executeQuery",
    "query": "INSERT INTO users (user_id, username, first_name)\n\
              VALUES ( {{ $json.message.from.id }},\n\
                       '{{ $json.message.from.username }}',\n\
                       '{{ $json.message.from.first_name }}')\n\
              ON CONFLICT (user_id) DO UPDATE\n\
              SET username   = EXCLUDED.username,\n\
                  first_name = EXCLUDED.first_name;"
  },
  "id": "3",
  "name": "Supabase Upsert User",
  "type": "n8n-nodes-base.supabase",
  "typeVersion": 1,
  "position": [650,0],
  "credentials": { "supabaseApi": "" }
}
```

> Аналогично для всех остальных Supabase/Postgres-нод (вставка сообщения, выбор последних 100 и т.д.).

### 2) Или оставить *insert/upsert*, но перейти на новую структуру

Пример для Supabase-Insert:

```jsonc
{
  "parameters": {
    "operation": "insert",
    "table": "chat_history",
    "columnsUi": {
      "values": [
        { "name": "session_id" },
        { "name": "user_id"    },
        { "name": "username"   },
        { "name": "role"       },
        { "name": "content"    }
      ]
    },
    "valuesUi": {
      "values": [
        {
          "value": [
            "={{ 'user_' + $json.message.from.id }}",
            "={{ $json.message.from.id }}",
            "={{ $json.message.from.username }}",
            "user",
            "={{ $json.message.text }}"
          ]
        }
      ]
    },
    "additionalFields": {}
  },
  "id": "4",
  "name": "Supabase Insert Chat History",
  …
}
```

### Памятка для будущих правок

* Проверяй в UI: если у ноды есть вкладка **“Columns”** с таблицей — в JSON это *columnsUi.values* → массив объектов `{ name }`.  
* Любой массив значений внутри ноды должен попадать в `.values` (или `.options.values`).  
* Поля, где ничего не надо — оставляй `additionalFields:{}` (пустой объект).

Поправь ноды одним из двух способов выше — и workflow загрузится без ошибок. Если застрянешь на конкретной строке — дай знать, пришлю готовый фрагмент.

### что ещё может потребоваться

| Что | Где править | Комментарий |
|-----|-------------|-------------|
| **Токен Telegram** | `credentials.telegramApi` в `Telegram Trigger` и `Telegram Send` | BotFather → токен |
| **Supabase URL / key** | `credentials.supabaseApi` во всех Supabase-нодах | форм-дата: `url`, `anonKey/serviceRole` |
| **Postgres** | `credentials.postgres` в Postgres-нодах | host/user/pass/db |
| **OpenAI** | `credentials.openAIApi` | key + модель |

> После импорта — ​заполни креды, нажми *Activate workflow* и отправь любое сообщение боту.  
>   Если нужно вернуть обработку **voice / photo / document** — просто подключи соответствующие выходы `Switch` к своим пайплайнам (Speech-to-Text, OCR, etc.).

Теперь импорт пройдёт без ошибок, потому что **ни одна** Supabase/Postgres-нода не содержит устаревших `columns / values`, а только `executeQuery`.
