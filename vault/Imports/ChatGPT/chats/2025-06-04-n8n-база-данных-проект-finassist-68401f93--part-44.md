В **Structured Output Parser** задаём схему так, чтобы LLM _не смог_ «соскакать» без вызова `data_tool3`.  
Проще всего заставить его вернуть **строго-типовой JSON** c 4 полями:

```json
{
  "thought": "string",            // что я делаю
  "action": {
    "tool": "data_tool3",         // НИКОГДА не меняется!
    "query": "string"             // что ищу
  },
  "observation": "string",        // content из data_tool3
  "final_answer": "string"        // ответ пользователю (<150 слов)
}
```

---

### Как настроить

1. **Schema Type → Generate from JSON Example**  
2. В поле **JSON Example** вставьте именно этот объект.  
   n8n автоматически построит JSON-Schema «всё обязательно».  
3. Включите **Auto-Fix Format** — мелкие ошибки LLM поправит нода.  
4. В **AI Agent**:  
   * *Require Specific Output* = ON.  
   * В System Message оставьте жёсткое правило:  
     ```
     ТЫ ДОЛЖЕН вернуть JSON ровно с полями thought, action, observation, final_answer.
     action.tool ВСЕГДА "data_tool3". Иначе ERROR.
     ```

---

### Что произойдёт

* **Итерация 1**  
  * LLM формирует:
    ```json
    {"thought":"ищу инструкции","action":{"tool":"data_tool3","query":"..."}}
    ```
  * Parser проверяет — JSON валиден, но нет `observation` → запускается инструмент `data_tool3`.  
* **Итерация 2**  
  * LLM получает Observation, добавляет поля `observation` и `final_answer`.  
  * Parser пропускает только корректный JSON → в Telegram уходит ровно **один** ответ.  

> Если модель забудет вызвать `data_tool3`, Parser сочтёт JSON невалидным → node упадёт.  
> Можно повесить IF-нод → повторить запрос или вывести «Ошибка: вызови tool».

Такой шаблон надёжно заставляет GPT-4 (o-nano и др.) **каждый раз** обращаться к `DATA_TOOL3` прежде чем отвечать пользователю.

| **Аппаратные требования** | Облачные TPU-v5e / A100; локально не запускают | Запускаются на 8-16 GB VRAM (2B) или 24-32 GB (7B) |

Это пример **cURL-запроса к API Anthropic** (провайдера LLM-моделей «Claude»).

| Часть запроса | Что означает |
|---------------|--------------|
| `curl https://api.anthropic.com/v1/messages` | HTTP-вызов к эндпоинту `/v1/messages`, через который общаются с моделью Claude. |
| `--header "x-api-key: …"` | **Секретный ключ** доступа к вашему аккаунту Anthropic. Его никогда не публикуют — иначе любой сможет расходовать ваш баланс. |
| `--header "anthropic-version: 2023-06-01"` | Явно указывает версию API. В Anthropic это обязательный заголовок. |
| `--header "content-type: application/json"` | Говорит серверу, что тело запроса — JSON. |
| `--data '{ … }'` | Сам JSON-пейлоуд: |
|  `"model": "claude-3-5-sonnet-20241022"` | ID конкретной модели (Claude 3.5 Sonnet preview). |
|  `"max_tokens": 1024` | Сколько токенов разрешено сгенерировать в ответе. |
|  `"messages": […]` | Структура чата: массив объектов `{role, content}`. Здесь один юзер-месседж «Hello, world». |

**Итого:** запрос отправляет текст «Hello, world» в модель Claude 3.5 Sonnet и просит до 1024 токенов ответа. Ответ вернётся в JSON-формате с полями `role: "assistant"` и `content` — там будет сгенерированный ответ модели.

> **Важно:** ключ API на скриншоте/в примере нужно немедленно отозвать и сгенерировать новый; никогда не выкладывайте рабочие ключи в открытый доступ.
