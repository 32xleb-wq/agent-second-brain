### Коротко о главном  

* **Отдельного «GPTs API» пока не существует** – кастомные GPT-чат-боты из интерфейса ChatGPT не получают собственного эндпойнта. Вместо этого OpenAI предлагает **Assistants API** (а с марта 2025 г. ещё и более новую **Responses API**, которая к 2026 г. полностью заменит Assistants). citeturn6search1turn3news2  
* Поэтому, чтобы «подключить GPT к n8n», вы фактически подключаете **OpenAI API** (Chat Completions, Assistants или Responses) и воссоздаёте там логику вашего GPT.

## Как это сделать шаг за шагом

| Шаг | Что делаем | Где кликаем/какой узел n8n использовать |
|-----|------------|----------------------------------------|
| 1. Получаем ключ | Войдите на <https://platform.openai.com>, «API keys → Create new secret key». Сохраните сразу – потом не покажет. citeturn3search0 | — |
| 2. Добавляем учётные данные в n8n | **Settings → Credentials → OpenAI → New**. Вставьте ключ, при необходимости укажите организацию. | — |
| 3а. (Базовый способ) Chat Completions | Узел **OpenAI → Chat**; модель `gpt-4o` или `gpt-4.1`. В поле *System* вставьте инструкции вашего кастомного GPT. | OpenAI node |
| 3б. (Полный клон GPT) Assistants API | Узел **OpenAI → Assistant**. Сначала операция **Create Assistant** (имя, инструкции, файлы-знания, функции). Затем **Run Assistant** (создаёт thread, возвращает ответы). citeturn1search1 | OpenAI Assistant node |
| 3в. (Переход на Responses API) | Если у вас n8n v 1.30+ – используйте HTTP Request узел: `POST https://api.openai.com/v1/responses` с теми же заголовками `Authorization: Bearer YOUR_KEY`. Структура почти как у Assistants, но поле `messages` переименовано в `interactions`. citeturn3news2 | HTTP Request |
| 4. Проверяем лимиты | Модели GPT-4o/4.1 требуют «Pay-as-you-go» аккаунт, а у Responses API действует отдельный rate-limit. | — |
| 5. (Обратное направление) Даём GPT доступ к n8n | В самом ChatGPT добавьте **Action** и опишите ваш n8n-вебхук в формате OpenAPI. Тогда GPT сможет «тыкать» в ваш workflow напрямую. Пример такого подхода описан на форуме n8n. citeturn0search1 |

### Пример HTTP Request узла для Assistants API

```json
{
  "url": "https://api.openai.com/v1/threads/{THREAD_ID}/messages",
  "method": "POST",
  "headers": {
    "Authorization": "Bearer {{$credentials.openai.apiKey}}",
    "Content-Type": "application/json"
  },
  "body": {
    "role": "user",
    "content": "Привет, чем ты можешь помочь?"
  }
}
```

Затем вызов  
`POST https://api.openai.com/v1/threads/{THREAD_ID}/runs`  
с `assistant_id` вашего ассистента запустит поколение ответа. Все шаги можно собрать цепочкой HTTP-узлов, либо пользоваться готовым **OpenAI Assistant**-узлом, если он уже есть в вашей сборке n8n.

## Стоит ли ждать «настоящего GPTs API»?

OpenAI даёт понять, что **Responses API** станет «универсальным слоем» для агентов и заменит Assistants, а отдельного эндпойнта для GPT-чат-ботов по-прежнему не обещает. На практике же Responses/Assistants закрывают 99 % сценариев, а их узлы в n8n уже доступны и продолжают обновляться.
