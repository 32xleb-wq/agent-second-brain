## Как починить

> **2 минуты SQL** – ничего в n8n трогать не надо, нужно лишь создать (или переименовать) одну функцию-обёртку.

```sql
-- 1.  Если функция для system_documents уже есть (например match_system_documents) –
--    сделайте «alias» с нужным именем:
CREATE OR REPLACE FUNCTION public.match_documents(
    filter          jsonb        DEFAULT '{}',
    match_count     int          DEFAULT 5,
    query_embedding vector
)
RETURNS TABLE (
    id          uuid,
    content     text,
    metadata    jsonb,
    embedding   vector,
    distance    float
)
LANGUAGE sql STABLE PARALLEL SAFE
AS $$
    SELECT
      id,
      content,
      metadata,
      embedding,
      embedding <=> query_embedding  AS distance
    FROM system_documents   -- тут имя вашей таблицы
    WHERE (metadata @> filter)       -- простой JSON-фильтр
    ORDER BY embedding <=> query_embedding
    LIMIT match_count;
$$;

-- 2.  Обязательно GRANT EXECUTE, иначе PostgREST не увидит RPC
GRANT EXECUTE ON FUNCTION public.match_documents(jsonb,int,vector) TO anon, authenticated, service_role;
```

* **DATA_BASE3** остаётся как есть (`Operation mode: Retrieve Documents …; Query Name пустой → берётся default = match_documents`).  
* При выполнении нода будет звать новую функцию, получать `documents` с полем `content/metadata` → инструмент **DATA_TOOL3** увидит данные, а **AI Agent** наконец-то сможет вызывать `system_instructions` и строить ответы по правилам.

### Почему нынешний SQL-вариант не 1-в-1 как «Вариант A»

|                     | «Вариант A» (то, что мы пробовали сначала) | Итоговый рабочий вариант |
|---------------------|-------------------------------------------|---------------------------|
| **Сигнатура**       | `match_documents(filter jsonb DEFAULT '{}', match_count int DEFAULT 5, query_embedding vector)` | `match_documents(filter jsonb, match_count int, query_embedding vector)` |
| **Причина смены**   | PostgreSQL ⟶ ошибка `42P13`: *«input parameters after one with a default value must also have defaults»*. Нельзя ставить параметры **без** DEFAULT после параметра **с** DEFAULT. | Убрали DEFAULT-ы ⇢ сигнатура валидна. |
| **Язык функции**    | `plpgsql` с блоком `RETURN QUERY …`        | `LANGUAGE sql` — проще и быстрее, т. к. логика — один SELECT. |
| **Параллельность**  | не указана                                 | `PARALLEL SAFE` — позволяет планировщику выполнять поиск параллельно. |
| **Ключевой SELECT** | тот же, но писался «от руки»               | Такой же, но в чистом SQL — работает без обёртки PL/pgSQL. |
| **GRANT EXECUTE**   | не добавляли                              | Добавили, чтобы PostgREST-роль (`authenticated`, `anon`) могла вызывать функцию из n8n. |

#### Что реально изменилось

1. **Убраны DEFAULT-значения** ⇒ пропала ошибка `42P13`.  
2. **PL/pgSQL** заменён на **SQL-функцию** — меньше кода и меньше точек отказа.  
3. Добавлен **GRANT EXECUTE** — иначе Supabase API (и, соответственно, нода n8n) не видит функцию.  
4. В остальном (`embedding <=> query_embedding`, сортировка, LIMIT) логика полностью совпадает.

> Если вам нужно, чтобы `filter` или `match_count` были опциональными, делается в самом запросе из n8n:
```sql
SELECT * FROM match_documents(
        $filter::jsonb        -- передаёте {} если фильтра нет
      , COALESCE($k,5)       -- подставляете 5 когда $k = NULL
      , $embedding
);
```
Так мы не нарушаем правило порядка параметров, и не приходится держать две версии функции.
