## 3. Подключаем PostgreSQL к n8n

### 3.1. Использовать Postgres как **внутреннюю БД n8n**  
В `docker-compose.yml` (или в переменных окружения сервиса) укажи:

```yaml
environment:
  - DB_TYPE=postgresdb          # ключевая переменная, без неё n8n упадёт на SQLite
  - DB_POSTGRESDB_HOST=ep-foo-bar-123.us-east-2.aws.neon.tech
  - DB_POSTGRESDB_PORT=5432
  - DB_POSTGRESDB_DATABASE=neondb
  - DB_POSTGRESDB_USER=USER
  - DB_POSTGRESDB_PASSWORD=PASSWORD
  - DB_POSTGRESDB_SCHEMA=public
  - DB_POSTGRESDB_SSL=true      # для Supabase/Neon обязательно
```

> n8n переключается на Postgres **только** если видит `DB_TYPE=postgresdb`; иначе молча вернётся к SQLite. citeturn0search2turn0search8

После изменения переменных: `docker compose up -d` → проверь логи `docker compose logs -f n8n`, должно появиться `Migrations in progress … finished`.

### 3.2. Использовать Postgres как **узел в воркфлоу**  
1. В веб-интерфейсе n8n → **Credentials → New → Postgres**.  
2. Заполни Host, Port, Database, User, Password, включи `SSL` (если Supabase/Neon).  
3. Нажми **Test** — получишь «Connection successful».  
4. Теперь в любом воркфлоу добавляй **Postgres node** и выбирай эту учётку.

*(Через этот же credential можно писать/читать любую стороннюю БД, не затрагивая системную БД n8n.)*

## 3. Интеграционный слой (Orchestration / n8n-workflow)  
1. **Webhook / UI Trigger → “Onboarding”**  
   * Задаём наводящие вопросы → записываем ответы в `company_profile`.  
2. **Cron (ежедневно) → “Reminders”**  
   * Читаем календарь обязательств → отправляем email/Telegram.  
3. **HTTP + Generate Doc Node**  
   * При событии “Create Invoice/Act” → берём шаблон → генерируем PDF → кладём в S3 → создаём запись `document`.  
4. **Payroll Batch (2 р/мес)**  
   * SQL Select сотрудников → расчёт формулами → записываем `payout` → генерируем реестр выплат.  
5. **Backup Flow (ночной)**  
   * `n8n export:workflow` + dump БД в S3 → готовим DR-стратегию.

> Каждый подпроцесс — отдельный workflow; «железо» (Postgres, S3, Redis) развёрнуто через docker-compose рядом с n8n.

### Почему так?
* **Сгруппировано** — чтобы пользователь логически переходил от простого к специфике.  
* **Ветвления** (if/else) сокращают лишние вопросы: например, если «нет сотрудников» — блок payroll скрываем.  
* **Числовые градации** (0, 1-5, …) вместо свободного ввода → легче строить правила и фильтры.  
* **Enum + Multi-select** позволяют бот-UI реализовать быстрые кнопки (Telegram / WebApp).  
* **Приоритеты** сразу дают нам backlog, какие модули «включать» в личном кабинете.

## Что можно автоматизировать в n8n сразу

1. **Онбординг-воркфлоу**  
   * `Telegram Trigger` → `Switch` по ответам → `Set` профиль → `Postgres Insert`.  
   * По финишу — создаём задачи-шаблоны (напоминания) в `reminder_scheduler` таблице.

2. **Календарь обязательств**  
   * Cron раз в день → SQL select где `due_date - now() < 7d` → отправить пользователю.

3. **Динамические вопросы**  
   * Для ветвлений используем `IF` node: если `employee_count = 0` → skip payroll блок.
