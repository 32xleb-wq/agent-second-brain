Вот пошаговая инструкция по созданию правил брандмауэра в Google Cloud для разрешения доступа к портам **5678, 443 и 80**:

---

### **1. Открытие Google Cloud Console**
Перейдите в [Google Cloud Console](https://console.cloud.google.com/) и войдите в свою учетную запись.

---

### **2. Выбор проекта**
Если у вас несколько проектов, выберите нужный в верхнем левом углу.

---

### **3. Переход в настройки брандмауэра**
1. В меню слева откройте **VPC Network (Сеть VPC)** → **Firewall (Брандмауэр)**.
2. Нажмите кнопку **"Create Firewall Rule" (Создать правило брандмауэра)**.

---

### **4. Настройка правила**
Заполните следующие поля:

- **Name (Имя)**:  
  Например, `allow-ports-5678-443-80`.

- **Network (Сеть)**:  
  Выберите вашу сеть (обычно `default`, если не создавали свою).

- **Direction of traffic (Направление трафика)**:  
  Выберите `Ingress` (Входящий трафик).

- **Action on match (Действие при совпадении)**:  
  Выберите `Allow` (Разрешить).

- **Targets (Цели)**:  
  - Если хотите открыть доступ ко всем VM в сети, выберите `All instances in the network` (Все экземпляры в сети).  
  - Если доступ нужен только к определенным VM, выберите `Specified target tags` и укажите теги.

- **Source filter (Источник трафика)**:  
  Выберите `IPv4 Ranges` (Диапазоны IP).  
  Введите `0.0.0.0/0`, если хотите разрешить доступ из любой сети.

- **Protocols and ports (Протоколы и порты)**:  
  - Выберите **Specified protocols and ports**.  
  - Отметьте **TCP** и впишите порты:  
    ```
    5678, 443, 80
    ```

---

### **5. Сохранение правила**
Нажмите **"Create" (Создать)**.  

После этого правило появится в списке, и порты будут открыты.

---

### **Проверка работы**
Чтобы убедиться, что правило применяется, можно:

1. Проверить список правил в разделе **Firewall**.
2. Попробовать подключиться к вашему серверу на одном из разрешенных портов (например, через браузер для порта `443` или `80`).

Если что-то не работает, убедитесь, что:

- Приложение действительно прослушивает эти порты.
- В вашей виртуальной машине (VM) нет дополнительного брандмауэра, блокирующего трафик.

---

### **🚀 Пошаговое решение**

### **1️⃣ Проверьте, что n8n доступен извне**  
WhatsApp API требует **публичный URL**, а `localhost` или внутренний IP не подойдет.  

✅ **Решение:**  
Если n8n работает локально, используйте `ngrok`, чтобы создать публичный адрес:  
```sh
ngrok http 5678
```
Затем замените `Webhook URL` в Meta Developer Console на `https://your-ngrok-url/webhook`.

---

### **2️⃣ Проверьте, открыт ли порт 5678**  
Если n8n установлен на сервере (например, в Google Cloud, AWS), убедитесь, что порт **5678 открыт** для внешних соединений.  

✅ **Решение для Google Cloud:**  
1. Перейдите в `VPC Network > Firewall Rules`.  
2. Создайте новое правило **Allow Incoming Connections**.  
3. Укажите:  
   - **Target:** `All instances in the network`  
   - **Source IP range:** `0.0.0.0/0`  
   - **Allowed protocols and ports:** `TCP: 5678`  

---

### **3️⃣ Проверьте правильность Webhook URL в Meta Developer Console**  
1. Откройте [Meta for Developers](https://developers.facebook.com/)  
2. Перейдите в **WhatsApp > Webhooks**.  
3. Проверьте, что в поле **Callback URL** указан **актуальный URL n8n**, например:  
   ```
   https://your-public-url/webhook
   ```
4. Убедитесь, что **Verify Token** в n8n совпадает с тем, что в Meta.

---

### **4️⃣ Убедитесь, что сервер отвечает быстро**  
WhatsApp API требует, чтобы сервер **отвечал менее чем за 5 секунд**. Если n8n обрабатывает запрос долго, верификация не пройдет.
