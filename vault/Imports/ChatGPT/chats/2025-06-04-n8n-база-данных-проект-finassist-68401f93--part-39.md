### Почему теперь «function http_post(unknown, json, hstore) does not exist»

В Supabase установлен **расширенный http-client**  
`http (supabase_http)` версии 1.6+, где сигнатура **уже не**  
`http_post(url text, body json, headers hstore)` — она устарела.

Новая форма:

```sql
http_post(
  url text,
  request jsonb   -- тело + заголовки одновременно
) 
RETURNS jsonb
```

То есть заголовки и тело нужно объединить в один JSONB-объект.

## Исправленная функция `get_openai_embedding` для Supabase http 1.6+

```sql
create or replace function get_openai_embedding(txt text)
returns vector(1536)
language plpgsql stable parallel safe as
$$
declare
    resp jsonb;
begin
    resp := http_post(
              'https://api.openai.com/v1/embeddings',
              jsonb_build_object(
                'headers', jsonb_build_object(
                              'Authorization', 'Bearer sk-ВАШ_КЛЮЧ',
                              'Content-Type',  'application/json'
                           ),
                'body',    jsonb_build_object(
                              'model', 'text-embedding-3-small',
                              'input', txt
                           ),
                'timeout_milliseconds', 30000,
                'follow_redirects',      true
              )
            );

    -- ответ выглядит так: { "content": {…}, "status":200, … }
    return (resp->'content'->'data'->0->'embedding')::vector;
end;
$$;
```

>   Можно держать его в Var:

>   create secret openai_key value 'sk-...';
>   ```  
>   и брать `current_setting('openai_key')`.

| поле      | тип  | что содержит                 |

1. Указали правильный ключ OpenAI;

перегрузка — **два** позиционных аргумента:

```json
  "body":    { … },
  "timeout_milliseconds": 30000,
  "follow_redirects": true
}
```

Поэтому вариант с «третьим параметром headers» не найдён ⇒ `function http_post(…, jsonb, jsonb) does not exist`.
