Вот тот же код без HTML-разрывов и с минимальными комментариями – просто скопируйте целиком в SQL-редактор Supabase.

```sql
-- 1. Включаем расширение http (нужно один раз)
create extension if not exists http;

-- 2. Функция, которая берёт текст, запрашивает OpenAI
--    и возвращает embedding как vector(1536)
create or replace function get_openai_embedding(txt text)
returns vector(1536)
language plpgsql
as $$
declare
    resp json;
begin
    resp := (
        select content
        from http_post(
            'https://api.openai.com/v1/embeddings',
            json_build_object(
                'model',  'text-embedding-3-small',
                'input',  txt
            ),
            json_build_object(
                'Authorization', 'Bearer YOUR_OPENAI_KEY',
                'Content-Type',  'application/json'
            )::hstore
        )
    );

    -- resp -> 'data' -> 0 -> 'embedding' – массив из 1536 чисел
    return (resp -> 'data' -> 0 -> 'embedding')::vector;
end;
$$;
```

**Важно:**

1.  `YOUR_OPENAI_KEY` замените на ваш реальный API-ключ.  
2. Убедитесь, что колонка `embedding` в `system_documents` имеет тип `vector(1536)`:

```sql
alter table system_documents
  add column if not exists embedding vector(1536);
```

3. Теперь можно проставить векторы (для строк, где они ещё `NULL`):

```sql
update system_documents
set    embedding = get_openai_embedding(content)
where  embedding is null;
```

После этого индекс `ivfflat` создаётся без ошибок, а `DATA_TOOL3` начнёт находить инструкции.

## Почему вариант «внутри SQL без ключа» не работает

* **pgvector** хранит и сравнивает векторы, но **не генерирует** их.  
* Расширение `http` позволяет вызвать внешний API, однако для OpenAI этот запрос обязан содержать `Authorization: Bearer …`.  
* Встроенных в Postgres open-source моделей нет: даже pgvecto.rs / `pgml` всё-равно подтягивают внешний двоичный файл модели либо обращаются к API.

PostgreSQL-vector не позволяет «нарезать» столбец `vector` привычным синтаксисом `embedding[1:5]`.  
Сделайте одну из двух вещей:

| нужно | правильный синтаксис |
|-------|----------------------|
| **Посчитать число «пустых» строк** | ```sql SELECT count(*) FROM system_documents WHERE embedding IS NULL; ``` |
| **Показать первые 5 компонент** | ```sql SELECT id, left(content,120)       AS snippet,        (embedding)::float8[]          -- преобразуем в массив      [1:5]                     AS first5_dims FROM   system_documents LIMIT 5; ``` |

То есть сначала приводим `vector` к обычному массиву с помощью  
`(embedding)::float8[]`, а потом уже берём срез `[1:5]`.

> **Почему ошибка?**  
> Тип `vector` из расширения `pgvector` – это собственный тип, у которого
> нет оператора «[ ]». После приведения к `float8[]` — оператор становится
> доступен.

Попробуйте выполнить запрос ещё раз с указанной правкой — должно
отобразить первые пять координат каждого встроенного вектора.

## Как починить

#### 1. Подключите расширение *hstore* (одна строка)

```sql
CREATE EXTENSION IF NOT EXISTS hstore;
```

> На Supabase-фри планах это разрешено — команда выполняется мгновенно и ничего не ломает.

#### 2. (опционально) пересоздайте функцию, если вы её уже устанавливали до этого

```sql
CREATE OR REPLACE FUNCTION get_openai_embedding(txt text)
RETURNS vector(1536)
LANGUAGE plpgsql
AS $$
DECLARE
  resp json;
BEGIN
  resp := (
    SELECT content
    FROM http_post(
           'https://api.openai.com/v1/embeddings',
           json_build_object('model','text-embedding-3-small','input', txt),
           -- теперь hstore доступен
           hstore(ARRAY[
             'Authorization', 'Bearer YOUR_OPENAI_KEY',
             'Content-Type', 'application/json'
           ])
         )
  );
  RETURN (resp->'data'->0->'embedding')::vector;
END;
$$;
```

*(ключ можно хранить в Supabase → **Settings → Project → Secrets** и подставлять через `current_setting('openai.api_key')` — так безопаснее).*

#### 3. Заполните эмбеддинги, если ещё не делали

```sql
UPDATE system_documents
SET    embedding = get_openai_embedding(content)
WHERE  embedding IS NULL;
```

#### 4. Проверьте поиск

```sql

       left(content,120) AS snippet,

FROM   system_documents
```

```sql
FROM   system_documents
ORDER  BY distance
```
