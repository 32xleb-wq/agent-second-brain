## 2 . Функция-обёртка `get_openai_embedding()`  

```sql
-- Сохраните свой ключ в параметр БД, чтобы не светить его в явном виде
alter database postgres set openai.api_key = 'sk-................................';

create or replace function get_openai_embedding(txt text)
returns vector(1536)  -- Аda-002 = 1536
language plpgsql stable parallel safe as
$$
declare
    resp  json;
begin
    resp := (
      select content
      from http_post(
        'https://api.openai.com/v1/embeddings',
        json_build_object(
          'model',  'text-embedding-3-small',
          'input',  txt
        )::json,
        -- заголовки → hstore
        hstore(  ARRAY[
          'Authorization', 'Bearer ' || current_setting('openai.api_key'),
          'Content-Type',  'application/json'
        ] )
      )
    );

    return (resp -> 'data' -> 0 -> 'embedding')::vector;
end;
$$;
```

*Что мы сделали*  
*   `http_post()` отправляет JSON {model,input}  
*   заголовки передаём как `hstore` (требуется расширение)  
*   вытаскиваем `embedding` и приводим к `vector`.

## 5 . RPC-функция поиска `match_system_documents`

```sql
create or replace function match_system_documents(
    query           text,
    match_count     int      default 5
)
returns table(
    id       uuid,
    title    text,
    content  text,
    distance float
) language plpgsql stable as
$$
declare
    q_emb vector(1536);
begin
    q_emb := get_openai_embedding(query);

    return query
    select  id,
            coalesce(title,'')  as title,
            content,
            embedding <=> q_emb as distance
    from    system_documents
    order by embedding <=> q_emb
    limit   match_count;
end;
$$;
```

*Функция лежит в `public` → Supabase автогенерирует RPC `/rest/v1/rpc/match_system_documents`.*

### Почему возникает `permission denied to set parameter "openai.api_key"` в Supabase

* **В Supabase ни одна роль, кроме `supabase_admin` (и “внутреннего” суперпользователя Postgres), не имеет права изменять _глобальные настройки_ (`ALTER DATABASE … SET …`, `SET config`).**  
  Любая попытка задать собственный GUC-параметр (как `openai.api_key`) из UI или через ваш обычный коннект выполняется под ролью **`authenticated_user`** → она «видит» только то, что разрешено **безопасно**.

* **В бесплатном / pro-тарифах Supabase нет superuser-доступа.**  
  Поэтому команда  

  ```sql
  alter database postgres set openai.api_key = 'sk-…';
  ```  

  всегда падает с `42501` (недостаточно прав).
